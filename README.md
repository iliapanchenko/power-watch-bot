# Power Watch Bot

Телеграм-бот, який стежить за адресами в інтернеті та пише в чат, коли зв'язок із точкою зникає («світло зникло») і коли повертається («світло з'явилось», із тривалістю відключення).

Розгортається на Vercel, стан тримає в Neon Postgres, перевірку тригерить зовнішній cron.

```
[cron-job.org]  --щохвилини-->  GET /api/check
                                     |
                                     |-- TCP-конект --> 178.x.x.x:443   (твоя точка)
                                     |
                                     v
                              [Neon Postgres]  <- статуси, історія, підписники
                                     |
                                     v
                              Telegram: 🔴 Квартира — світло зникло

[Telegram]      --вебхук---->  POST /api/telegram   (команди: /status, /add, ...)
```

---

## Спершу прочитай це

**Потрібна адреса, доступна з інтернету.** Vercel — це чужа хмара, вона фізично не бачить твою домашню `192.168.1.1`. Працює:

- білий (публічний) IP від провайдера — статичний або через DDNS-ім'я типу `myhome.ddns.net`;
- будь-який пристрій із прокинутим портом: роутер із веб-мордою на WAN, камера, NAS, сервер.

Не працює: приватні адреси (`192.168.x.x`, `10.x.x.x`) і провайдери з CGNAT — там твого роутера з інтернету просто не існує. Якщо це твій випадок, потрібна інша схема: агент удома, який шле «я живий» у хмару. Скажи — переробимо.

**ICMP-пінга тут немає.** У serverless-функціях raw-сокети заборонені, тому замість `ping` бот робить TCP-конект у вказаний порт. Практично різниці мало, з одним приємним бонусом: `ECONNREFUSED` (порт закритий, але хтось відповів) теж рахується як «живий» — тобто роутер не зобов'язаний нічого відкривати назовні, достатньо щоб він відповідав RST замість тиші. Якщо роутер мовчить у всі порти, вкажи порт прокинутого пристрою.

**Бот бачить зв'язок, а не електрику.** Обрив у провайдера при цілому світлі виглядає точно так само, як відключення. Хибних тривог тим менше, чим стабільніший інтернет на точці.

## Розгортання

### 1. Створи бота

У Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` → збережи токен.

### 2. Заведи базу

У проєкті на Vercel: **Storage → Create Database → Neon (Postgres)**. Vercel сам додасть `DATABASE_URL` у змінні оточення.

Можна й окремо на [neon.tech](https://neon.tech) — тоді скопіюй connection string руками.

### 3. Залий код

```bash
git remote add origin git@github.com:<ти>/power-watch-bot.git
git push -u origin main
```

Далі на Vercel: **Add New → Project → Import** свій репозиторій. Фреймворк — **Other**, білдити нічого не треба.

### 4. Пропиши змінні оточення

Vercel → Settings → Environment Variables:

| Змінна | Значення |
|---|---|
| `BOT_TOKEN` | токен від BotFather |
| `DATABASE_URL` | з'явиться сам, якщо Neon підключено через Vercel |
| `CRON_SECRET` | довгий випадковий рядок, напр. `openssl rand -hex 24` |
| `ADMIN_IDS` | (необов'язково) твій Telegram id, щоб керувати міг лише ти |
| `FAIL_THRESHOLD` | (необов'язково) скільки тиш поспіль = відключення, типово `2` |
| `OK_THRESHOLD` | (необов'язково) скільки відповідей поспіль = світло є, типово `2` |
| `PROBE_TIMEOUT` | (необов'язково) таймаут конекту в мс, типово `4000` |

`CRON_SECRET` тут працює одразу як пароль до `/api/check` і як підпис вебхука від Telegram — стороння людина, яка вгадала URL, нічого зробити не зможе.

Після додавання змінних зроби **Redeploy**.

### 5. Ініціалізуй

Відкрий у браузері один раз:

```
https://<твій-проєкт>.vercel.app/api/setup?key=<CRON_SECRET>
```

Ця ручка створює таблиці, реєструє вебхук і меню команд. У відповідь має прийти `{"ok":true,...}`.

### 6. Постав cron

На [cron-job.org](https://cron-job.org) створи задачу:

- **URL:** `https://<твій-проєкт>.vercel.app/api/check`
- **Schedule:** every 1 minute
- **Headers:** `Authorization: Bearer <CRON_SECRET>`

Секрет можна передати і в URL (`/api/check?key=...`), але заголовок акуратніший — не світиться в логах.

### 7. Увімкни

Напиши боту `/start`, потім додай точку:

```
/add myhome.ddns.net:443 Квартира
/add 178.12.34.56:80 Дача
```

## Команди

| Команда | Що робить |
|---|---|
| `/start` | підписати чат на сповіщення |
| `/status` | стан усіх точок і скільки він уже триває |
| `/check` | перевірити негайно, не чекаючи cron |
| `/list` | точки з деталями: хост, порт, остання перевірка, затримка |
| `/history` | останні 15 подій |
| `/add host[:port] Назва` | додати точку (порт типово 443) |
| `/rm <id або host>` | прибрати точку |
| `/stop` | відписатись |
| `/id` | показати свій Telegram id — для `ADMIN_IDS` |

Працює і в групі: додай бота в чат і напиши `/start` там.

## Як приймається рішення

Кожна перевірка — до двох спроб TCP-конекту. Статус міняється не з першої тиші, а за гістерезисом: `FAIL_THRESHOLD` провалів поспіль → «світло зникло», `OK_THRESHOLD` відповідей поспіль → «світло з'явилось». Без цього один загублений пакет о третій ночі будив би тебе двома повідомленнями поспіль.

При хвилинному cron і типових порогах реакція — приблизно 2 хвилини. Хочеш швидше — постав `FAIL_THRESHOLD=1`, але приготуйся до випадкових хибних тривог.

## Локальна перевірка

Чи взагалі відповідає адреса, перш ніж її додавати:

```bash
node scripts/probe-test.mjs myhome.ddns.net 443
node scripts/probe-test.mjs            # вбудовані приклади
```

Запуск усього проєкту локально:

```bash
npm i -g vercel
cp .env.example .env    # заповни
vercel dev
```

## Якщо щось не так

**Бот мовчить на команди.** Перевір, чи `/api/setup` відпрацював, і подивись `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` — там буде `last_error_message`.

**Точка завжди 🔴, хоча світло є.** Найчастіше адреса недосяжна ззовні: CGNAT, або роутер дропає все на WAN. Перевір `scripts/probe-test.mjs` з чужої мережі (мобільний інтернет, не свій Wi-Fi). Спробуй порт реально прокинутого пристрою.

**Статуси стрибають.** Підніми `FAIL_THRESHOLD` до 3-4 або `PROBE_TIMEOUT` до 8000 — при поганому каналі конект не встигає за 4 секунди.

**Тиша від cron.** Смикни `/api/check?key=...` руками — має прийти JSON зі списком перевірених точок. Якщо помилка про неіснуючу таблицю, зайди ще раз на `/api/setup`.

**Динамічний IP змінився.** Тому й краще DDNS-ім'я замість голого IP — інакше після переобрання адреси бот стежитиме за чужим підключенням.
